# Блок 15 — Сховище даних на файлах

[English](./README.md) · **Українська**

> ℹ️ Джерело істини — англійська версія ([README.md](./README.md)); український переклад може незначно відставати.

Простий спосіб зберігати дані без бази: тримати JSON-файл і завантажувати/зберігати його.
Ми обгорнемо це в **типізований узагальнений репозиторій** — патерн за багатьма
маленькими інструментами.

## Цикл load → mutate → save

Кожна операція читає поточний стан, змінює його й записує назад:

```ts
const items = await load();      // прочитати + розпарсити JSON-файл
items.push(newItem);             // змінити в памʼяті
await save(items);               // серіалізувати + записати назад
```

## Обробка «файлу ще немає»

Перше читання падає з `ENOENT`, бо файл ще не створено. Трактуй це як «порожньо», а решту
перекидай далі:

```ts
async function load(): Promise<T[]> {
  try {
    return JSON.parse(await readFile(path, "utf8")) as T[];
  } catch (err) {
    if ((err as NodeJS.ErrnoException).code === "ENOENT") return [];
    throw err;
  }
}
```

## Узагальнене, типізоване сховище

Обмеження `T` до `{ id: number }` дає сховищу реалізувати пошук і видалення:

```ts
class FileStore<T extends { id: number }> {
  constructor(private filePath: string) {}
  // load/save надані; ти реалізуєш all/get/add/remove
}
```

> Це наївне сховище щоразу переписує весь файл і небезпечне за конкурентного запису —
> нормально для CLI чи малого сервісу, але не для високонавантаженого сервера.

## Вправи

Відкрий [`src/exercises.ts`](./src/exercises.ts) і реалізуй методи `FileStore`. Потім
запусти:

```bash
node --import tsx --test "blocks/15-file-backed-store/tests/*.test.ts"
```

(`load` і `save` надані.)

1. `all()` — повернути кожен елемент (`[]`, коли файлу ще немає).
2. `get(id)` — повернути елемент із цим `id` або `undefined`.
3. `add(item)` — додати елемент і зберегти.
4. `remove(id)` — видалити за `id`; повернути `true`, якщо щось видалено, інакше `false`.
